# Producing documentation inside a support team

Combining support and documentation has real advantages. Writers get direct user
feedback and see real use cases. Writers who also do support can fix a doc mistake
themselves instead of handing it to another department. Support agents with a writing
role can turn repeated answers into docs.

## Support agent moving into writing
- **Different direction:** in support, users bring the question. In docs, you anticipate
  questions before they are asked, choose topics yourself, and define the audience.
- **Different feedback loop:** docs are usually peer-reviewed, and you review others' work.
  It can feel like supervision, but it is a safety net against publishing wrong information.

## Writer moving into support
- **You'll get questions about features you didn't document.** Don't be alarmed. Ask
  colleagues, study old tickets, and read the docs.
- **There's no review safety net.** Most support answers go out unchecked. Never give an
  answer you aren't sure of just to save face. Ask another agent or escalate.

## Writer in a dedicated docs role within support
A writer at a large SaaS company juggles doc gaps, versions, and release notes, and
can't take tickets too. Staying close to support still pays off. Three tactics:

1. **Get the team on board.** You are one team. Better docs mean fewer repetitive
   tickets, so the tickets that remain are more interesting.
2. **Simplify communication.** Support agents are busy, so make reporting doc issues
   effortless: a dedicated email address, a chat command or form that creates a doc
   task, or a shared board. If one channel doesn't work, try another.
3. **Collaborate.** Give the agent who reported an issue partial ownership. They review
   the draft to confirm it answers the problem, with no gaps. Thank them visibly.

## Agent checklist for setting up a support–docs loop
- [ ] An intake channel for doc issues, with a template: ticket link, user question,
      current doc URL, what's wrong or missing
- [ ] Triage cadence and an owner
- [ ] Review step by the reporting agent
- [ ] Metric: repeat tickets on topics that are now documented
- [ ] Docs links built into support macros and canned replies
